# 抓取范围与所属应用

## 实际范围

本程序是本地 HTTP/HTTPS 代理和媒体资源识别器，不是网卡全流量抓包工具，也不是完整网络请求日志工具。

1. 开启抓取会设置当前用户的系统代理。只有使用该代理（或显式指定本程序代理地址）的连接才会进入本程序。
2. 明文 HTTP 的响应可直接识别；HTTPS 需要应用信任本程序证书，并且域名符合设置中的 HTTPS 解密规则。默认规则是 `*`。不匹配规则的 CONNECT 连接只透传，无法读取其中的媒体响应。
3. 普通资源按响应 Content-Type 与配置的 MIME 映射识别，处理 200/206/304 响应；视频号另通过页面脚本中的媒体元数据提取资源。
4. 最终列表展示匹配的视频、图片、音频等资源，不展示所有 HTML/JSON/业务请求。资源按现有 URL 签名去重。

应用绕过系统代理、独立代理配置、QUIC/UDP、其他非 HTTP 协议、证书绑定或不信任本程序证书等情况不保证抓取。默认 `*` 表示尽可能解密经过代理的 HTTPS 域名，不等于能抓取整台电脑所有流量。

## 所属应用的含义

Windows 在接收 TCP 连接时，通过系统 TCP 连接表匹配客户端 IP/端口和本地代理 IP/端口，取得连接所属 PID，再读取进程可执行文件名。IPv4/IPv6 都支持；每条连接识别一次，HTTP 与 HTTPS CONNECT 内的请求继承这项信息。

- “所属应用”列展示实际连接进程名，例如 `chrome.exe`、`WeChat.exe` 或 `msedgewebview2.exe`，支持多选筛选并与其他列组合。
- 详情显示首次抓取时的进程名与 PID，不代表该 PID 当前仍属于同一个进程。
- 浏览器中打开的平台仍归属于浏览器进程；不把 qq.com 推断成微信。WebView 子进程不自动推断宿主应用。
- 如果流量先经过另一层本地代理，识别到的可能是那层代理进程。
- 无权读取进程名、连接未匹配、历史记录、导入数据缺少字段，或 macOS/Linux 尚未实现本地进程识别时，显示“未识别”；能取得 PID 时仍在详情显示 PID。
- 不保存进程完整路径，不新增驱动或管理员权限要求。
- 保留原来的资源去重行为，同一资源由多个应用请求时记录首次抓取来源，不是所有请求来源的统计。

## 筛选边界

“所属应用”和其他表头筛选只过滤已有列表，不改变系统代理，不停止其他应用的流量进入代理，也不修改抓取范围。按进程限制系统代理流量是另一项功能，不在本次变更中。

## 验证

- Windows 真实 IPv4/IPv6 回环 TCP 连接测试，验证 PID 和可执行文件名属于测试进程。
- HTTP/HTTPS 代理回归测试验证连接来源信息沿请求链保留。
- TCP 表解析测试覆盖完整四元组匹配、端口不符与截断数据。
- 普通媒体和视频号插件测试覆盖来源字段传递；前端缓存测试覆盖字段保留与旧历史兼容。
- 前端 8 项测试、Go 全部测试、go vet、生产前端与 Windows amd64 Wails 构建通过；Linux/macOS 核心交叉编译通过。
- GUI 使用测试数据验证 WeChat.exe 筛选后仅显示匹配行和 99 条计数，也验证“未识别”选项。截图为 `design-assets/source-app-filter.png`，不是实际微信抓取结果。
- fix3 ZIP 的可执行文件哈希与本次构建一致；真实微信/浏览器业务流量仍需用户实机复测。

## fix4：完整资源地址去重

- 新抓取事件按 `Url` 完整字符串合并，不再依赖可能缺失或不同的 `UrlSign`。
- 重启时自动整理重复历史；重复导入保留已有条目；下载任务恢复按地址匹配已有记录，避免旧缓存与当前任务各显示一行。
- 重复历史优先保留下载中的任务，其次是已完成及保存路径。重新抓取的请求头、解密信息等会刷新，任务 ID、状态和保存位置保留。
- 视频号在拼接 urlToken 后计算去重标识，使它与实际地址及普通媒体识别一致。
- 完整地址相同才合并，不删除查询参数、不忽略签名、不排序参数；不同签名/画质地址仍区分，避免误删可用资源。
- 保留原有的同地址下载任务防重复保护。本次只整理列表记录，不删除已经下载的文件。
